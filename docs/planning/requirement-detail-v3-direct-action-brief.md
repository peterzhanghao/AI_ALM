## 一、重构判断

当前页面不直接，主要因为“提示用户做事”和“让用户把事做完”分离了。

| 截图里的具体问题 | 用户实际付出的成本 | 本轮处理 |
| --- | --- | --- |
| 顶部“需要你回答”、底部“当前：需要你回答”与“回答并继续” | 三次看到状态，仍不知道问题是什么 | 待决策区直接展示问题与回答控件 |
| “查看问题”与底部按钮分处两端，还会打开另一层 | 找入口、离开正文、再理解一次上下文 | 在详情原地回答，只有必要证据另开层 |
| 默认“需求”页，而当前操作藏在“交付”或弹窗 | 用户先学信息架构，才能处理事项 | 一个默认概览：当前事项 → 需求内容 → 本轮结果 |
| “目标”下面紧接“背景”，其后是长原话 | 不清楚哪些是正式约定、哪些只是来源 | 已有正式条款按含义展示；只有原话时直接呈现原话 |
| “正文尚未明确：范围、验收要求”黄色提示，却让人去列表向 AI 澄清 | 在详情发现问题，必须退出详情处理 | 缺项在原地补充，或原地请求整理草案 |
| “已有用例 4”放在缺少业务验收要求的正文中 | 数量像完成信号，却不解释验证什么 | 有条件正文才显示；用例数放入可展开验证信息 |
| 抽屉内又套 720px 居中容器，头部、正文、页脚对齐不同 | 视线来回跳、宽度利用不稳定 | 一条左对齐阅读轴，减少容器嵌套 |
| 固定底栏重复状态、刷新、记录、免责声明 | 主要按钮远离问题，长期占据高度 | 按钮紧随内容；长表单只在按钮离屏时显示简短粘性操作条 |

设计目标：用户打开详情，能立刻说出“这条需求要改什么、现在到哪、我现在要做什么”，并在当前页面完成决定。页面以真实任务内容为中心。

如果用用户所说的乔布斯式产品标准检视，应把每个可见元素都当成需要解释其存在理由的成本。这里采用的具体取舍是：给详情完整空间，以真实目标建立理解，用当前任务形成视觉中心，让用户直接完成决定。不能以“乔布斯会认可”替代实际可用性验证。

## 二、直接交给 DSH 的执行指令

请实际重构当前需求详情页面，按以下结构实施，不止修改字号、颜色和边距。复用现有运行、决策、验收、授权与反馈能力，保护所有既有未提交修改。执行前核对适用仓库约定与当前源码；只修改本任务涉及部分，不重置他人的工作。

### A. 默认页面改成一页概览

**详情改为插件内容区内的独立页面，替换遮罩抽屉作为默认入口。** 宿主应用导航保持可见；列表在同一插件路由/视图中被详情替换，详情不覆盖到宿主窗口标题栏或菜单栏。不要全窗口 fixed 定位，不盖住其他应用入口，也不把模态焦点限制带进普通页面。

上方一条轻工具栏：“← 返回需求”在左，反馈、更多在右。详情使用返回导航，不显示模态关闭 X。返回恢复列表原筛选、搜索、排序、滚动位置与选中项；保存详情内部状态，重入时回到该对象合理位置。浏览器后退与页面返回遵循同一规则，有未保存输入时明确处理，不静默丢弃。原深链、刷新和从反馈进入具体对象仍能定位，不只保存在内存 selectedId 中。

默认不再显示“需求 / 交付 / 记录”主导航。把用户当下要完成的任务和需求内容放在一个连续页面中。运行详情、历史和技术证据分别通过明确链接进入子视图，支持返回并恢复位置。旧深链映射到对应新区域，不能使历史链接失效。

“详情全屏”指占满插件自身可用区域，不是接管整个桌面。默认单列，无常驻右侧属性栏，不保留一半变暗又不能操作的列表。快速预览如以后确有需求可以另做，不作为本轮默认路径。

建议骨架：

```text
[← 返回需求]                                  [反馈] [更多]

需求查询条件和列表优化
〈已确认目标的一句原文；没有就省略，不凭标题生成〉
REQ-ALM-001 · P1 · 张浩 · DSH（ALM）

等你决定
〈从当前有效决策读取的真实业务问题〉
〈仅当必要时：一句话说明决定会影响什么〉

○ 〈真实选项 A〉
   〈一句实际影响；推荐时明确标“AI 建议”，不预选〉
○ 〈真实选项 B〉
○ 我有其他想法
  〈补充内容〉

[确认选择并继续]
──────────────────────────────────────────
需求内容                                      [编辑]
〈真实目标/正文，简明并完整保留约束〉

本次包含
〈实际存在的范围；没有就显示原地补充入口〉

怎样算完成
〈实际存在的可观察验收条件〉

背景与原话                                      [展开]
──────────────────────────────────────────
本轮结果
〈真实最新结果、预览入口或一个明确问题〉
[查看运行详情]   [查看历史]
```

以上是结构示意，尖括号内容不能写死。截图里没有展示具体决策正文，本轮不能凭标题编造用户正在被问什么。

无待决策时，“等你决定”整个区域消失或变为符合实际的简短进展区，不保留空卡片。当前任务区、正文区、结果区不能都再包一层同样重量的卡片。

### B. 首屏显示内容，少说状态

标题是第一视觉层级；需求 ID、负责人、优先级、项目在一行低强调文字中。版本和复制入口可放“更多/详情”，不要在标题上方再占完整大行。标题长时正常换行，不任意剪掉关键内容。

标题下允许一句短目标，必须来自有效正文：它给眼前决定提供上下文。不要把全段原话塞进这里；没有可直接引用的独立目标就省略，正文仍在下方完整展示。任务区的具体问题使用 20–22px 小标题，优先于“等你决定”状态标签。第一屏的信息顺序固定，不因轮询在阅读中重排。

任务区使用“等你决定”“AI 正在处理”“可以验收”等简短标签，标签后立即是具体内容：

- 等你决定：真实问题、选项、必要的影响、回答控件。
- AI 正在处理：最近一个真实完成动作和当前动作；不以 runId、文件路径或未经证据支持的百分比代替进展。
- 处理暂停：一句已知原因与可执行恢复动作。
- 可以验收：完成了什么、预览/打开结果、怎样验证，以及人类验收入口。
- 已验收：验收结论与对应交付时间，发布状态单独表述。
- 尚未开始：需求内容在前，一个“交给 AI 推进”入口即可。
- 已关闭：关闭原因和必要历史，保留只读事实。

禁止用“AI 需要你的决定，确认后继续推进”作为有实际问题时的主体文案；它没给用户任何决策信息。通用说明只在确实缺数据时作为过渡状态，随后加载真实内容。

活跃事项最多突出一个；如果确有多项独立决定，显示“本次有 2 项需要决定”并按顺序原地作答。不能只显示第一项却让按钮代表用户确认了全部。

### C. 决策直接在详情里完成

复用或提取 `AnswerRunModal` 中现有结构化决策渲染与提交逻辑，形成可在详情内使用的 `DecisionForm`（名称按项目约定）。旧回答入口也使用同一个组件，避免新旧两套行为。

读取当前有效决策的 presentation、问题、选项、影响和推荐说明。推荐必须有明确来源，标记“AI 建议”，默认不选。任一会改变授权范围的选项都需要用户实际选择，不靠页面打开、默认值或阅读视为同意。

回答交互：

1. 明确问题在前，选项紧随；多行文字点整行可选；选中态和焦点态清晰。
2. 各选项说明只呈现能影响选择的内容，命令、路径、日志、哈希进入“查看依据”。选项长文可展开，但不能藏掉关键影响。
3. 输入完毕后，在该组内容下方显示唯一主按钮“确认选择并继续”。多题时明确本次提交哪些决定。
4. 保存中锁定本次提交，成功文案区分“回答已保存”和“AI 已恢复”：后者必须有服务端真实回执。没有恢复成功时保留已保存答案和继续入口。
5. 失败保留选项与补充内容；焦点到错误附近，给具体恢复动作，不关详情、不回列表、不清空表单。
6. 决策版本发生变化，展示变化并要求用户重新核对。不能把针对旧问题的选择自动套到新问题。
7. 成功后原地替换为“你已选择：……”和真实运行反馈；不强制切 tab、关闭详情或跳到通用会话。
8. 展开原始决策、滚动、阅读、复制都不能触发回答或恢复执行。

兼容缺数据：

- 加载中用局部骨架，正文仍可读。
- 读失败：显示“暂时读不到需要你决定的问题”与重试；不显示空白选项、不允许继续。
- 只有旧 Markdown：只读展示当前问题原文；有可可靠解析的选项就结构化展示，不能靠实时模型改写冒充原问题。
- 明确缺少选项/影响：说明“这条请求没有给出可供选择的方案”，提供原地补充回答能力（若现有协议支持），或只读整理草案入口。整理不消费决策、不扩授权，不自动恢复开发；确认时仍绑定服务端实际决策版本。

不要为界面舒服而重写 decision 生命周期：保留路径+内容哈希绑定、resolvedDecisions 消费回执、CAS/幂等、旧问题不复活，以及“继续本轮”与“重新启动”的真实区别。内部标识用于校验，默认无需让用户阅读。

### D. 正文自然阅读，缺项原地补

“需求内容”是正文区入口，不机械输出目标、范围、验收三个空标题。

展示规则：

- 有结构化正式目标/范围/验收时，按“要改什么 / 本次包含 / 怎样算完成”表达，保持原意、条件、例外与否定约束。短条目直接展示。
- 只有背景或用户原话时，标注“原始诉求”，直接显示这份实际内容。不要在它上面硬套“目标”，再在内部重复输出“背景”。
- 缺少范围/验收时，在正文相关位置给一个安静的“尚未明确 · 补充”入口，或者一行“还差范围和验收要求”并带“在这里补充”。不再做第二块黄色告警。
- 原地编辑保存失败留在原处，保留文本；退出编辑时检测未保存内容。后端复核修订，不能无提示覆盖其他人的修改。
- 若已有模型整理能力，可提供“让 AI 整理草案”：显示修改前后、标记建议来源，用户采纳后才成为正式内容；不在打开详情时调用模型生成新的已确认承诺。
- 文本来源、AI 建议、历史记录按元数据分开，不用标题正则猜作者。只做完全相等的可逆展示去重，不吞掉长段落附加约束。
- 已采纳且已写入有效需求的条款进入正文；“已采纳但尚未写入”保留为建议处理记录，不能假装已落盘。

如果当前 run 正在等一个具体决定，同时正文有缺项，优先处理当前决定；缺项是否阻塞推进由真实规则决定。不能因为页面发现缺项就突然另开澄清流程、丢掉原 run。需要重新确认范围时，明确告知影响和切换。

用例与验收：正文显示业务验收条件；关联用例数量是次级入口，不能用“4 个测试”替代“怎样算完成”，也不能把数量当作通过数。最近测试的版本、结果与证据在“本轮结果”展开查看。

### E. 结果先讲交付，再提供记录

本轮结果回答：改了什么，能否查看，哪些验证已完成，哪里还没完成。所有结果必须有真实字段或证据引用。

等待验收时在这里提供真实预览、逐条业务验收结果和“验收通过 / 退回修改”操作。验收的对象、版本和影响需要用户可见；具体哈希按需展开。不能把 AI 测试通过改成人类验收通过。

未到交付时不放空洞的“质量 0/5、证据 0、发布未授权”仪表盘。真实执行失败显示与当前任务有关的一个具体原因和恢复入口；历史失败和已关闭缺陷进入历史。

“查看运行详情”“查看历史”“查看依据”进入插件内子视图或明确的侧级页面，不叠套多个模态。返回后恢复阅读/编辑现场。技术细节保留完整可达性：原始请求、命令、stdout/stderr、版本、候选、审计和源文件都能查，但不默认占据主流程。

### F. 操作位置与滚动规则

- 每个状态只有一个当前主动作，紧邻它对应的问题或结果。取消、反馈、更多、查看历史作为次级操作，不和主动作同等强调。
- 去掉默认常驻的“当前：…… / 刷新 / 查看记录 / 主按钮 / AI 免责声明”大底栏。
- 长决策表单需要操作固定可达时：观察原地提交按钮，只有它离开可视区才显示紧凑粘性操作条，原按钮进入视区后隐藏。屏幕上最多一个可见的相同提交按钮；粘性条不重复状态长文。
- 不在滚动时自动抢焦点、不因轮询成功滚回顶部；用户手动阅读历史时不自动切回任务。
- 基础阅读保持一条纵向滚动轴。顶部返回入口固定可达，返回列表时焦点恢复原条目。Escape 只关闭当前菜单/证据层或取消当前编辑，不在普通详情页突然退回列表；普通页面不设置 `aria-modal`、dialog role 或全页 focus trap。

保留必要授权确认，但只在相关操作发生时说明对象、范围与后果；不在所有页面固定打印技术性免责声明。

### G. 视觉规格：安静、清晰、可以操作

沿用宿主主题 token 和系统中文字体；不新增外部字体、CDN 或品牌渐变。主内容用实际插件区域宽度布局，不根据整窗宽度误判可用空间。

- 详情占满插件内容区，阅读列内容宽至多 800px（加两侧32px padding 后外宽864px）；实际插件可用宽度小于 960px 时左右内边距 24px，小于 640px 为 16px。大屏居中的是**整条阅读轴**：标题、任务、正文、结果使用同一个容器，禁止每块独立居中。取消旧“880px 抽屉中再居中720px”的双重容器。单列每行约 35–45 个汉字，长内容可左对齐收窄，不靠拉宽字号解决。
- 标题 24–28px、正文 15–16px、行高 1.6 左右、次级信息 12–13px。真实中文内容下校准，不用截图物理像素直接当 CSS px。正文在缩放后仍清晰。
- 标题、任务区、正文左边缘误差不超过 2 CSS px；默认宽度下元信息不无故分成三行。
- 普通区块间距约 24–32px，块内 8–12px；用留白与少量分隔线组织，不连续套大卡片。
- 颜色只表达当下需要处理的异常；正在开发不是黄色告警。待决定使用低饱和轻底或细线，只突出一处。正常文字与可操作文字清晰区分，达到适用对比度。
- 控件热区建议至少 40px 高；选项长行完整换行，不水平滚动。链接要有明确点击线索，不把全屏都做成灰色下划线文字。
- 单页不出现三种近义状态标签，主按钮文案明确表达这次动作。
- 反馈入口保留在标题工具区；宿主浮动部件遮挡时预留合理安全区，不让徽标挡住选项、错误或按钮。不擅自移除不属于插件的宿主组件。
- 仅保留有目的的轻过渡，尊重 reduced-motion；不做装饰性加载动画。

### H. 具体实现落点

#### 开发前先固定五种屏幕，而非逐块增加组件

同一页面骨架仅更换一个任务区；由纯投影选择主情境。不按不同状态再复制五套详情页。

| 情境 | 首屏视觉中心 | 主动作与位置 | 不该出现 |
| --- | --- | --- | --- |
| 尚未开始 | 真实目标与已确认范围 | 正文末端“交给 AI 推进” | 空进度、空验收卡、待发布提示 |
| 等待决定 | 真实业务问题与选项 | 问题末端“确认选择并继续” | 另一个查看问题入口、页面底部重复主按钮 |
| 运行中 | 当前动作与最近一条有效结果 | “查看运行详情”为次级入口；取消进入运行控制 | 虚构进度百分比、可点的新建推进按钮 |
| 中断/失败 | 对用户有意义的原因和保留了什么 | 原因后“恢复推进”或“重试”，依真实能力 | 泛化“操作失败”、暗示记录已丢失 |
| 待验收 | 可打开的交付成果与待核对结果 | 先查看交付；需核对内容可见后再展示验收操作 | 把已测试当已签收、默认立即发布 |

“尚未开始”时不要把按钮悬在标题角落，用户还没看到范围就被要求启动；“等待决定”时不要把长背景放到问题前。页面重心由当前任务决定，但完整需求仍可连续阅读。

#### 排版与组件约束

- 页面工具栏高约 56px，固定于插件内容区顶部，不随宿主窗口 fixed。标题区顶留白 28–40px；标题与元信息/目标相距 8–12px。任务区与标题区相距 28px，正文区距任务区 32–40px。
- 使用 4/8px 间距体系，颜色映射宿主语义 token。交互参考中的深色/浅色色值只用于演示，不能复制成插件硬编码配色。
- 选择行最小高 64px、内边距 16px、间距 8px；默认细边框，选中才有强调边框与轻背景。文字左对齐，radio 与第一行对齐，禁止整列文本垂直居中造成长选项难扫读。
- 任务区只允许一层容器，不再套“当前待办”卡→问题卡→选项卡→提示卡。示例采用单一安静表面与选项行边框，其余用留白组织。
- 主要按钮高 44px，桌面按文案自然宽度，窄屏可占满行；图标不能替代动作文字。反馈/更多视觉退后但有清晰 accessible name。
- 无内容时不为对称保留区块。来源、历史的展开行带实际名称；不要出现“更多信息”“详情”等无法预测内容的万能链接。
- Loading 避免布局大跳：优先保留已知标题与正文，任务区局部加载；加载失败就地替换。后台更新通过 live region 简短通知，不反复读出整个详情。
- 焦点样式与选中样式不同；文本/交互对比度分别按适用 WCAG AA 校验，200% 缩放与长中文都要实际看图。

#### 交互预算与视觉评审

固定常见夹具（一行/两行标题、单题两选项、每选项不超过两行、无超长影响说明）在 1280×800 的实际插件区域中：目标、完整问题、至少两个选项与提交入口应在首屏。超长真实问题可自然滚动，不靠裁掉风险、缩小文字或隐藏第二题满足首屏指标。

- 单题选择到继续：一次选择 + 一次提交，不加“查看问题”、切页签或无新增语义的二次确认。不可逆动作或新增权限需要的独立确认保留。
- 正文阅读到补充：点击“补充”即可原地输入，不先跳源文件或列表。退出失败保留编辑现场。
- 从列表进入再返回：一次返回动作恢复原现场，不重新初始化筛选。跨需求切换不携带上一个对象的回答。
- 交付输出真实前后同尺寸对照，说明移除了哪些重复状态、首屏增加了哪些可行动内容。对照截图不是仅截组件，要包含宿主导航和插件实际边界。
- 用一次 5 秒内容定位检查评估：能否指出需求目标、当前问题、下一步位置。由未参与实现的人实际执行才记用户验证；自己看图只能记设计检查，不以名人审美或通过单测代替。

配套参考仅使用一个预设的示例问题说明“原地决策”，不代表截图里真实的待答内容。页面文字必须根据实际数据调整，不从参考抄成生产数据。

### I. 验收：用真实内容和实际操作评审

先基于固定数据做布局和组件检查，再用加载了本轮新代码的真实宿主验证。单元/模拟传输与真实宿主结果分开汇报，不能用 32/32 或 40/40 的旧数字认定本轮体验已合格。

| 检查 | 本轮必须达到的行为 |
| --- | --- |
| 当前截图同类情境 | 打开详情即可看到实际问题和可操作答案，不点“查看问题”、不切页签、不另开回答弹窗 |
| 内容清晰 | 标题/真实当前事项/已有需求正文有稳定阅读顺序；没有“目标”套“背景”的空壳层级 |
| 缺正文 | 原地知道还差什么，并能补充或生成待确认草案；不用退出详情回列表 |
| 单题/多题 | 单题直接答；多题明确数量与提交范围；未选择不提交，不预选推荐 |
| 成功反馈 | 只有真实恢复回执后显示 AI 已继续；运行记录仍关联原需求和本轮决策 |
| 失败与陈旧 | 请求失败保留输入；决策变化拒绝旧答案并展示变化；重试不重复消费 |
| 旧数据 | 旧 Markdown 可读；缺选项/读失败不伪造结构、不意外授权 |
| 进行中/中断 | 正确显示真实活动与恢复语义，旧决策不复活，continue 不误走 start |
| 待验收 | 结果、预览、逐条验证在前，签收真实绑定候选；不自动验收、不自动发布 |
| 阅读与滚动 | 无默认大底栏；按钮邻近内容，离屏才粘性显示；无重复可见主按钮，底部内容不被挡 |
| 响应式 | 插件实际宽 360/480/640/880/960/1280px 及 200% 缩放下，无横向溢出、选项可达、正文不遮挡；不是仅改变整窗 viewport |
| 键盘 | Tab 顺序与阅读顺序一致；radio 箭头选择、Space、Enter、Escape、焦点返回实际验证；普通详情无模态焦点陷阱 |
| 页面承载 | 在插件区内显示完整详情，无半屏变暗列表；宿主导航与窗口操作可用；返回恢复列表状态、焦点与滚动 |
| 不丢数据 | 刷新/重入、需求切换、未保存离开均有明确行为；旧响应不覆盖新对象 |

保存至少八种真实数据状态的页面证据：待决定完整选项、多决定、读失败、旧版缺选项、AI 运行中、中断、待验收、只有原话的需求。模拟状态只在隔离夹具中建立；真实业务决定不由验证器冒充人类提交。

布局检查之外做一个简短任务走查：从列表打开待决定需求，让未参与实现者指出当前问题并找到回答位置，记录是否误点和是否需解释。没有独立走查条件时，明确“未做独立可用性验证”，不自称用户满意。

### J. 交付要求

完成实际实现、相关回归、真实宿主只读走查与隔离场景提交验证。输出：

1. 修改文件和行为变化，尤其是旧入口到新入口的映射。
2. 默认详情与决策处理的前后对照图，附实际插件版本/宿主加载身份。
3. 八种状态截图、真实提交/失败保留/陈旧拒绝的证据，明确哪些为夹具、哪些为真实宿主。
4. 测试结果与仍未覆盖项；有失败先定位并如实汇报，不能沿用历史全绿。
5. 一份简短交付说明，回答：现在打开详情，用户看到的第一件具体事情是什么，能否原地处理，哪些信息需要展开。

不要自动签收、授权发布或修改真实需求以造演示效果。没有实际实现与加载验证，不得仅凭静态原型宣布完成。

## 三、与上一版指令的关系

本指令替换上一版的默认抽屉布局、回答入口与底栏设计；继续沿用已有统一状态投影、后端门禁、真实证据、来源与版本保护。不是再减少几个标签，而是把“查看状态之后去别处操作”改为“在具体问题处直接处理”。
