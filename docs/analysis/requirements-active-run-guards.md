# 执行状态一致性与默认待处理修复

## 用户问题

列表显示推进中，详情却依据旧验收失败显示开始修复；执行中仍存在冲突写入口；需求列表默认全部而非待处理。

## 实现

- 详情投影将真实 running/queued 的活跃运行置于旧失败、旧阻塞之前，主动作仅查看推进；旧证据保留供查看。关闭、已发布与等待人工回答仍遵守各自优先级。
- 客户端列表执行中优先查看推进，归档/删除禁用。详情验收、签收、发布、AI 优化、变更试演、归档、删除、处理缺陷八个冲突 handler 不提供；取消与只读入口保留。
- 服务端冲突写入在副作用前重新检查，返回 HTTP 409 / run-busy。启动锁覆盖异步载体创建窗口；Windows 路径大小写与分隔符归一化；先 reconcile 陈旧运行，避免永久锁死。
- 缺陷确认同时检查所属需求及 impact.requirement，避免通过确认另启迭代绕过门禁；预览仍可查看。
- 首次进入、切换项目默认待处理，包含尚未完成的需求，排除已验收（含已发布）和已关闭。待我处理仍为独立视图；清除全部筛选有意切到全部。
