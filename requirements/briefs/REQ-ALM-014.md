# REQ-ALM-014 需求澄清判决式重构与运行时缺陷自愈

## 目标
把需求澄清从表单填报改造为带证据的判决流程，并让需求插件在运行期遇到缺陷时自动采集、分类、自愈与验证，不再依赖人工复制粘贴报错。

## 问题与场景
近 20 次澄清会话中 17 次模型调用失败，Grill 澄清 0 次生效；失败后由关键词规则回填伪草稿且仍可确认入库；失败不写入 .alm/failures，因此插件既无法澄清清楚，也无法自我修复。用户遇到缺陷时只能手工复制报错到主对话。

## 验收要求
- AC-01澄清链路的 5xx 失败必须写入 .alm/failures，带 runId、model、timing 与去重指纹，重复失败累加 occurrences。
- AC-02首 token 超时与输出超时两类缺陷必须能被自动分类，并通过调整自愈策略参数后重跑同一会话，验证首 token 到达且分析成功。
- AC-03模型未参与时不得生成 problem 与 acceptance，界面必须显示未澄清且禁止一键确认。
- AC-04判决必须落在八种结果之一（create/extend/revise/merge/split/decline/defer/answer），缺少必要条件的判决不得入库。
- AC-05拒绝必须写入否决账本并可被后续查重命中，包含理由、替代方案与再提触发条件。
- AC-06自愈策略只允许调整参数与模型链，不得修改源码；每次策略变更必须可回滚并记录历史。
