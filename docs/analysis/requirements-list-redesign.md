## 3. 设计取舍

1. **行是数据，不是卡片。** 桌面端用一套 grid 列宽（`minmax(260px,1fr) 116px 100px 88px 196px 112px`）稳定对齐；需求列最宽，标题 14px/600，ID 用等宽字体 + 低强调版本号；行高 68px，异常行自然增高。宽屏 6 列，<1120px 折叠成需求/状态/检查/操作，<760px 只留需求/操作。
2. **业务状态与检查结果分开。** 业务状态是 `status` 胶囊；检查结果是“决策状态 + 一句原因”，中性（未检查）不用错误色，失败/阻塞/过期才用少量语义色，且都带文字，不靠颜色单独表达。
3. **每行只给一个真实动作。** 由 `decision.state + topGap.code` 映射：处理 / 重跑验收 / 重新验收 / 登记验收 / 运行验收 / 运行评审 / 查看评审；没有动作时退回“打开”。没有把“下一步”做成装饰文本，也没有保留每行“详情”按钮——标题本身是详情入口（可聚焦、Enter 打开、hover 下划线）。
4. **重复 ID 是两条记录。** 行标识和详情定位都用 `occurrenceKey`（`UID@file:line`），重复记录分别打开；异常行第三行写“需求 ID 重复 · 涉及 2 条记录”，来源记录保留、不自动合并。
5. **提示条只占一行。** 数据异常提示与检查提示压到 43px 高，保留“只看异常/查看原因/筛选”入口；当 check 失败完全由数据异常解释时不再显示“0 个门禁缺口”。
6. **数量真实且随搜索变化。** 状态标签数量按当前搜索关键字计算，搜索 + 状态筛选组合后数字与列表一致；“全部”标签显示搜索结果总数。
7. **刷新不闪空、不丢现场。** `useRequirements` 刷新时保留旧数据，只在首次加载显示骨架屏；刷新中按钮文案变“刷新中…”并禁用；刷新保留搜索与筛选。
8. **空状态与错误都可理解。** 无需求时显示“还没有需求”并给出真实“新建需求”入口；请求失败时把 `root not found` 这类引擎错误翻译成中文可操作说明（含“更多 → 指定根目录”指引），保留重试入口。
9. **“打开仓库目录”是真的。** 宿主端新增 reveal 路由，校验目录后用 `explorer.exe/open/xdg-open` 打开；打不开时在列表上给出明确失败原因，不伪装成功。
10. **键盘与焦点。** 标题按钮可 Tab 聚焦并用 Enter 打开详情；Drawer 打开后 Esc 关闭，关闭后列表、筛选、搜索、滚动位置都保留；更多菜单支持 Esc 与点击外部关闭。
