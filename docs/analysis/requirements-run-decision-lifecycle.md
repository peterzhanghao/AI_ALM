# REQ-ALM-001 卡住：决策生命周期与同轮继续

## 真实原因

原 RUN-001 已保存三次人类回答，其中包含按范围内证据提交评审的明确授权。但 `checkpoint.decision` 一直指向旧决策，回答并未消费该决策。每次执行器 idle 又无条件进入等待人工状态，因此旧问题不断复活。恢复到新会话时提示仅携带本次回答，没有结构化保留此前授权与限制。

另一条独立死路是：详情的“继续推进”指向新启动流程；后端发现原运行仍 active 便直接复用返回，没有发送 followup，实际没有继续执行。

真实环境拒绝（此前受限执行器的 `spawn EPERM` 与浏览器 socket 目录不可写）仍是独立事实，不能靠消费决策、改标签或降低验收标准解决。

## 产品修复

- 决策身份按明确引用路径与当前文件 SHA256 绑定。回答同次持久化追加消费回执 `checkpoint.resolvedDecisions`，保留历史回答、检查点与原始文档，清除当前待回答引用。
- 只对精确匹配的路径与内容回执认定已回答；touch 不产生新问题。新内容、读失败、旧无绑定回答均不能隐式吞掉人工门禁。不按修改时间扫描、猜测新决策。
- idle 仅有新的未解决显式决策时等待人工；否则为结果交接，不再复活旧问题。
- 恢复提示携带所有已确认回答、最新检查点与已消费决策，明确不能重复请求相同授权。
- “继续推进”使用独立 `run / mode: continue`，续原需求原运行，不追加伪造的人类回答、不走新建派单。
- 回答携带所读决策身份；内容变化拒绝提交。继续与回答均不得绕过待决策、读失败、暂停或取消。
- 前端对 `resumed: false` 显示实际错误，不冒充提交成功。
- 恢复保留 `workspace-write` 与 `approval never`，不提升权限、不改验收配置、不自动签署或发布。
