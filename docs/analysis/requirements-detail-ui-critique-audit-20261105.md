# 需求详情 UI Critique 与技术 Audit

日期：2026-11-05。对象：`packages/dsh-plugin-requirements/client-source.js` 的需求详情三页签与需求澄清界面。

## 方法与证据边界

- 使用 `impeccable` 的 critique/audit 评审标准；当前安装的 CLI 只提供 `detect`，调用 `critique` 与 `audit` 均返回 `Unknown command`，所以本记录不是技能命令生成的报告。评审包括主上下文实机观察和独立代码/设计复核；自动检测另行记录。
- `impeccable detect --json packages/dsh-plugin-requirements/client-source.js` 返回 `[]`。该扫描是源码启发式检测，空结果不代表无障碍或视觉验收通过。
- 按 `web-design-guidelines` 指定 URL 获取了最新规则，并静态核对语义、焦点、表单、响应式、长内容、性能和主题处理。
- Playwright 隔离浏览器回归验证澄清窄屏、详情页签键盘导航与取消未保存切页，以及运行对话、轨迹和用量；最新全仓 Node 测试 1198/1198 通过。测试没有运行真实 Desktop 内嵌 WebView。
- 宿主性能契约补充：DSH `sessionQuery` README 明确 `readSession` 是完整日志回放，`observeSession` 通过 revision cache/lease 复用 cold prepared session，但没有历史事件范围读取。插件现优先使用 observation lease；这降低重复读盘，不把响应分页误称为存储分页。
- 版本契约核对：DSH 0.2.2-rc.1 的 `dsh-session-query` 实现公开接受 `projectionMode: 'none'`，仍返回事件并跳过投影计算；插件接入方式与宿主代码契约一致，lease 释放后由宿主缓存保留 prepared session。
- 真实用量补充：当前工作区 `RUN-001 / REQ-ALM-001` 的 session 与本机 `billion-context` 精确匹配，真实只读观察返回 30 次请求、缓存命中率 87% 和约 `$1.0278` 的代理估算；覆盖标为不完整且未生成运行合计。该证据验证归属链路，不等于供应商账单或 Desktop 画面验收。
- 代理节省显示补充：如果 billion-context 返回 `savedUsd`，详情页仅显示为“上下文节省估算（代理估算，非账单）”；货币格式使用 `Intl.NumberFormat`，不假设固定前缀。缺失时不显示节省额。
- 当前真实运行的 `savedUsd` 和 `savedUsdGross` 均为 `null`，因此页面保持未知，不把缓存命中 token 换算成虚构节省金额。
- 更早一次检查时，Windows UI 清单没有可选 DSH 顶层窗口；本次用户打开窗口后已通过 Computer Use 完成只读验收。整个过程未重启或重载用户会话。

补充实机运行态（`REQ-ALM-001 v1`）：AI 进展页显示运行状态“等待输入”、最近活动、过期验收和发布限制；会话回放返回“宿主报告记录损坏；原始记录仍被保留”。点击“在 DSH 中打开会话”后，Desktop 确实导航到运行绑定的 session `alm-CHG-ALM-001-mw36lymj`，但 DSH 随后报告 seq 7 缺少 message ID，历史内容无法回放。原生导航接线通过；宿主旧 session 数据完整性、成功模型流和完整账单仍未证明。

## Critique

需求详情属于 DSH 的高频操作界面。页签、对话、轨迹和账本按工作职责组织，运行状态、未知用量及敏感信息处理明确，方向与宿主紧凑工作区相符。隔离回归显示 320px 下核心流程可用；这只能证明构造的测试数据和 Chromium 环境。

手工 Nielsen 启发式评分（代码与隔离浏览器证据，不是实机评分）：

| 启发式 | 分数 / 4 | 依据与边界 |
| --- | --- | --- |
| 系统状态可见 | 3 | 运行状态、更新时间、轮询和未知/损坏状态有呈现；真实宿主转态尚未观察 |
| 贴近现实语言 | 3 | 业务详情、AI 进展、历史、对话/轨迹/用量命名清晰；部分技术事件仍直接暴露 |
| 用户控制与自由 | 3 | 页签方向键、历史运行/会话选择、刷新与回到最新已实现；主机热重载未实测 |
| 一致性与标准 | 3 | 使用宿主 DSW token 和 ARIA tab 模式；真实 DSH 深色主题观感一致，但未做像素级对比和对比度测量。 |
| 错误预防 | 3 | 跨页未保存保护、状态门禁和不可信费用归属提示；读屏无法验证 |
| 识别而非回忆 | 3 | 当前状态、运行编号、会话段和信息来源就地显示；旧运行元数据仍需加载 |
| 灵活与效率 | 3 | 键盘切页、分页、运行跳转、原生会话入口；Desktop 原生跳转未实测 |
| 简洁与信息层级 | 3 | 正文、进展和时间线分工；技术事件与成本明细仍是高密度信息 |
| 错误恢复 | 3 | 查询重试、迟到事件重放、损坏日志提示和失败路径有覆盖；真实代理恢复未测 |
| 帮助与文档 | 2 | 控件自带恢复提示，但没有实机帮助入口和读屏播报证据 |
| **合计** | **29 / 40** | **暂定：源码和模拟环境，不代表 Desktop 体验或 WCAG 合规** |

### 优先问题与处理

| 优先级 | 问题 | 影响 | 处理 / 后续 |
| --- | --- | --- | --- |
| P2 | 三页签横向布局未明确支持长标签、文字放大与窄容器滚动。 | 超窄面板或放大时标签可能挤压，键盘当前页签可见性不稳。 | 已给 tablist 增加横向自动滚动、滚动链约束和触控横向手势；标签固定宽度并保留键盘焦点。详情浏览器回归验证 `overflow-x:auto`。 |
| P1 验收项 | 真实 DSH 浅色主题、屏幕阅读器、200% 缩放和原生会话跳转没有 Desktop 证据。 | 深色实机截图和 AX 树不能证明浅色主题对比度、读屏播报、系统缩放或跳转行为。 | 保留为发布前人工实机验收项；不能由浏览器夹具替代。 |
| P2 验收项 | 真实大日志渲染与历史业务时间线的高数据量性能未在 Desktop 实测。 | 当前测试只测分页接口/投影，不包含真实宿主 SQLite 查询、WebView 和实际渲染。 | 真实数据量和宿主环境可用后测首屏、滚动与内存，再决定是否窗口化。 |

## Web Interface Guidelines Audit

| 维度 | 当前证据 | 结论 |
| --- | --- | --- |
| 可访问性 | 详情页签使用 `tablist` / `tab` / `aria-selected`、方向键/Home/End；焦点样式来自详情页 CSS；澄清输入有可访问名称和弹窗焦点约束。 | 源码和 Chromium 键盘回归良好；屏幕阅读器、真实对比度和宿主 focus ring 未验证。 |
| 性能 | 历史运行按页加载；事件文本限长并提供详情续读；实时轮询合并为 4s/15s，运行终止后停止。模拟 5000 事件单页投影中位约 5ms。 | 代码路径有界；数据非真实宿主，不能推断 Desktop 端到端性能。 |
| 主题 | 主要颜色从 DSH `--dsw-alias-*` token 读取，含回退值；实机观察到 DSH 深色主题。 | 深色主题与宿主一致；浅色主题、回退组合及对比度数值仍未核验。 |
| 响应式 | 澄清对话框和详情在 320px Chromium 下通过滚动/边界断言；页签现支持横向滚动。 | 320px 隔离验证；600px、200% 缩放和不同宿主容器待补实机证据。 |
| 文本与状态 | 长正文可换行和续读；请求失败可重试；无数据、损坏、未知费用均有明确状态。 | 代码证据较好；真实环境下颜色、焦点遮挡和系统缩放待验。 |

补充响应式证据：隔离 Chromium 在 240px 宽度并将页签文字放大到 24px 后，End 键切换到末尾页签会把焦点页签滚入 tablist 可视范围，页面无横向溢出。该模拟缩放仍不等于真实 Desktop 200% 缩放。

### 实机 Critique 补充

- **P2：历史页空状态的纵向密度偏松。** `REQ-ALM-003` 没有运行数据时，时间线与运行历史各有空状态，后面仍连续显示多组折叠元数据区，导致视口下半部主要是分隔线和标题。建议在无数据时将相关元数据组收进一个“更多需求信息”折叠区；数据存在时再恢复独立分组，保留当前按领域查找的能力。
- **P2 验收项：右下角宿主挂件与密集运行内容的遮挡关系未验证。** 当前空状态截图中挂件位于正文右下侧，没有覆盖可见文本；若真实对话/轨迹延伸到同一视口边缘，需要以运行态确认滚动末尾内容和键盘焦点不会被挂件遮挡。挂件属于 DSH 宿主，不建议仅凭空状态截图改写插件布局。
- **Sam（依赖辅助技术）红旗**：AX 树有清晰 tablist/tab/tabpanel 关系，初步支持识别页签；NVDA/讲述人实际播报、方向键焦点移动和异步状态播报尚未测，不能据此判定可访问性通过。
- **Alex（高频操作）红旗**：AI 进展在无运行记录时仍保留“交给 AI 推进”主操作和“刷新状态”，流程入口明确；有历史运行时是否能快速定位目标运行、本次实机没有数据可验证。
- **Jordan（首次使用者）红旗**：推进说明、业务验收不默认通过、运行历史不足不等于没有历史等提示均使用直白文案；“归属关系”“证据追溯”等历史页标题的实际内容是否易懂，需展开后结合真实数据再审。

本次使用当前 `web-design-guidelines` 源规则静态核查源码，并通过真实 DSH AX 树和截图核对语义与视觉。Impeccable `critique` / `audit` CLI 子命令在已安装版本不可用，因此评分和上述评语是依据该技能的手工评审标准形成，不是 CLI 生成报告。实机未能证明的项目均明确保留为发布验收项。

## 需求澄清页 Critique 与 Audit（2026-11-05）

评审对象为 `IntentModal` 的输入、分析、回答、候选、确认和回执状态。真实 DSH Desktop 只读打开了“新建需求”入口，AX 树确认以下控件实际存在：

- 对话框标题“你想改变什么？”和关闭按钮；
- 原话编辑框“用你自己的话写下想改变什么”；
- “查看服务端意图历史”“＋ 图片”“从聊天记录补充”“手动填写候选”“分析意图”；
- 宿主提示“DSH · 先澄清，不会创建需求”，说明入口不会绕过确认直接写入需求。

实机截图层在本次窗口上未稳定捕获弹层内容，因此以下视觉判断以源码、隔离 Chromium 和 AX 树为主；没有提交原话、上传图片、分析意图或保存草案。

优先问题：

- **P1（已处理）：确认页一次性暴露过多决策面。** 初始实现把问题/目标、范围、未知项、去向、影响预览、产物、负责人和优先级连续堆叠。现将范围/未证实信息默认折叠，将产物/权限信息按需折叠；新建路径需要优先级时自动展开权限区，保留服务端门禁。隔离浏览器验证默认折叠和优先级区自动展开，真实 HTTP 确认流程通过。
- **P2：输入页的辅助动作和主输入竞争注意力。** 图片、聊天补充、历史和手动候选都位于同一弹窗，且真实窗口截图无法确认窄尺寸下的折叠顺序。继续保持“分析意图”为唯一主操作，辅助动作应使用次级视觉并在 320px 下保持可达。
- **P2：分析阶段使用模糊玻璃和阴影。** `backdrop-filter: blur(6px)` 与大阴影在低端设备和宿主 WebView 上成本较高；应保留遮罩层级，用 `prefers-reduced-motion` 与性能实测决定是否降低模糊。
- **P2：候选字段的可访问名称现在依赖动态 `aria-label`。** 已补充稳定 `name`，但仍需 NVDA/讲述人确认多意图与增删验收行的朗读顺序。

### Web Interface Guidelines Audit 结果

- **已修复**：通用输入样式移除内联 `outline: none`；详情/弹窗的 `:focus-visible` 规则继续提供焦点轮廓。
- **已修复**：`ModalShell` 以 `aria-labelledby` 关联标题，分析态设置 `aria-busy`，滚动容器设置 `overscroll-behavior: contain`。
- **已修复**：澄清原话、聊天记录、回答、候选字段、负责人、优先级和问题组回答补充 `name`；动态提示使用 `role=status` / `aria-live=polite`。
- **已修复**：图片缩略图显式提供宽高，移除图片按钮触控尺寸提升到 24px；图片仍有文本替代和状态标签。
- **保留风险**：输入页的“＋ 图片”使用可聚焦 `label[role=button]`，真实读屏和键盘触发需继续验证；输入框 placeholder 仍是示例而非标签，当前已有 aria-label。
