# REQ-ALM-009 原生意图服务端历史发现与同 session 安全恢复

## 目标
使当前明确选定项目内服务端已保存、模型已结束的原生意图在刷新后可被发现，并以同一 session ID 和最新版本恢复，避免用户重复分析。

## 问题与场景
当前已有“保存并离开”及服务器 session 存储，但刷新页面后缺少历史入口，用户需要重复分析。

## 详细功能
### FR-01 服务端意图历史入口
- 行为：提供当前明确选定项目内服务端已保存、模型已结束的意图列表。
- 前置：当前项目已明确选定。
- 前置：意图已保存至服务端且模型已结束。
- 响应：列表至少展示 sessionId、状态、更新时间。
- 边界：不能用仅 localStorage 最近指针替代服务器历史。
- 边界：列表读取只读，不自动分析、创建或确认。
- 来源：user-input#L1
- 来源：user-input#L2

### FR-02 同身份完整恢复
- 行为：选中历史意图后恢复同一 session ID、最新版本、原输入、候选内容、四字段验收、route 与已解决 unknown。
- 前置：选中的意图属于当前项目并符合恢复范围。
- 响应：恢复后可继续既有编辑、保存、确认流程。
- 边界：恢复加载只读，不自动分析、创建或确认。
- 边界：旧 revision、未解决 unknown、失效 context/docHash 及可信人工确认等现有门禁保持不变。
- 来源：user-input#L1
- 来源：user-input#L2

### FR-03 已 committed 意图原结果展示
- 行为：已 committed 意图只显示原 receipt，并提供打开原需求的能力。
- 前置：意图已 committed。
- 响应：重复打开仍指向原结果。
- 边界：不能重新创建或再次确认。
- 边界：不得生成额外 REQ、INT、receipt 或 run。
- 来源：user-input#L2

### FR-04 项目隔离与迟到响应防护
- 行为：当前合法项目之间隔离；切项目或关闭弹窗后的迟到成功和失败均不得覆盖新状态。
- 前置：发生项目切换、弹窗关闭或异步请求乱序返回。
- 响应：迟到响应不覆盖新状态，项目数据保持隔离。
- 边界：不得为恢复开放任意目录或绕过 workspace 权限。
- 来源：user-input#L2
- 来源：user-input#L3

### FR-05 显式失败与编辑保护
- 行为：不存在、非法路径或加载失败时提供明确错误和重试；保存失败时保留编辑。
- 前置：加载不存在的意图、使用非法路径、加载失败或保存失败。
- 响应：错误明确且可重试；保存失败不宣称保存成功。
- 边界：不得静默创建新草稿。
- 来源：user-input#L2

## 本次范围
- 当前明确选定项目的服务端已保存、模型已结束意图列表与恢复。
- 既有编辑、保存、确认流程的恢复衔接及原门禁保留。
- 真实 handler 临时隔离存储、实际 client 行为及同一现有 Desktop 的业务验证。
- 候选和原生构建激活 GUI 验证。

## 不包含
- 未分析或未保存的本地内容恢复。
- 后台模型跨进程续跑。
- 跨设备同步。
- 全文搜索、分页产品化、历史 diff。
- 自动修复存储。
- 自动签收或发布。

## 验收要求
- AC-01（FR-01、FR-02）同一现有 Desktop 完成真实保存、刷新、发现历史、同 ID 同字段恢复，以及编辑保存后再次恢复。
  - 前置：使用同一现有 Desktop，并有当前明确选定项目内服务端已保存、模型已结束的意图。
  - 动作：真实保存后刷新页面，查看历史并选择恢复，再编辑、保存并再次恢复。
  - 预期：历史可见且至少显示 sessionId、状态、更新时间；恢复同一 session ID、最新版本、原输入、候选内容、四字段验收、route 与已解决 unknown；再次恢复反映已保存编辑。
  - 判定：核对真实 Desktop 行为及上述身份、版本和字段，通用 pnpm test 不替代此业务验证。
  - 来源：user-input#L1
  - 来源：user-input#L4
- AC-02（FR-03）已有 committed 意图重复打开只展示原结果，不产生额外产物。
  - 前置：存在已有 committed 意图及其原 receipt 和原需求。
  - 动作：重复打开该意图并打开原需求。
  - 预期：只展示原 receipt 和原需求，不重新创建、再次确认或生成额外 REQ、INT、receipt、run。
  - 判定：核对重复打开前后的原结果与产物变化。
  - 来源：user-input#L2
  - 来源：user-input#L4
- AC-03（FR-01、FR-02、FR-04）真实 handler 和实际 client 测试验证只读加载、A/B 项目隔离、非法输入与乱序响应防护。
  - 前置：真实 handler 使用临时隔离存储，并覆盖实际 client 行为及 A/B 项目场景。
  - 动作：读取列表和加载意图，测试非法 ID、非法路径、不存在的意图，并在切项目或关闭弹窗后制造迟到成功、迟到失败和乱序响应。
  - 预期：列表与加载只读且不自动分析、创建、确认；项目隔离；非法输入或不存在时明确报错、可重试且不静默创建草稿；迟到响应不覆盖新状态；不绕过 workspace 权限。
  - 判定：核对真实 handler 隔离存储测试、实际 client 行为测试及对应业务验证记录。
  - 来源：user-input#L2
  - 来源：user-input#L3
  - 来源：user-input#L4
- AC-04（FR-05）加载失败可明确重试，保存失败保留编辑且不宣称保存。
  - 前置：存在可加载的意图以及尚未成功保存的编辑内容。
  - 动作：测试加载失败和保存失败，并检查客户端展示与编辑内容。
  - 预期：加载失败明确报错、可重试且不静默创建新草稿；保存失败保留编辑且不宣称保存成功。
  - 判定：核对实际 client 行为及加载、保存失败测试记录。
  - 来源：user-input#L2
  - 来源：user-input#L4
- AC-05（FR-02）恢复后原门禁负例仍被阻止，独立冻结判据不因产品失败而修改。
  - 前置：具备旧 revision、未解决 unknown、失效 context/docHash 和可信人工确认相关的原门禁负例。
  - 动作：恢复意图后测试上述原门禁负例，并对照独立冻结判据记录验证结果。
  - 预期：原门禁保持，不通过恢复绕过；独立冻结判据只读记录于 tmp/requirements-native-loop-observation，不修改判据掩盖产品失败。
  - 判定：核对原门禁负例结果、冻结判据及真实业务验证记录；通用 pnpm test 不替代业务验证。
  - 来源：user-input#L2
  - 来源：user-input#L4

## 必要约束
- Core 保持无 DSH/网络依赖，目标为 Node22。
- 不得为恢复开放任意目录或绕过 workspace 权限。
- 旧 revision、未解决 unknown、失效 context/docHash 及可信人工确认等现有门禁必须保留。
- 独立冻结判据只读记录在 tmp/requirements-native-loop-observation，不能改判据掩盖产品失败。
- 通用 pnpm test 不能替代指定业务验证。
- 用户提出由插件自行负责开发、原运行修复、登记验收、候选和原生构建激活 GUI 验证，不由当前对话 API 接力代办；本草稿只记录该要求，不构成执行授权。
