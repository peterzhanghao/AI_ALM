# 决策请求：识别不了旧格式时怎么显示

## 要决定什么
遇到不符合新格式的旧决策请求，是整份原文照旧展示，还是尽量提取出可选择的决策项再展示？

## 背景
- 仓库里已经存在两份旧格式决策请求，短期内不会重写。
- 新格式要靠执行器按模板生成，旧文件可能一直存在。
- 直接显示原文最省事，但这次反馈的问题会在旧文件上原样复现。

## 决策 1：旧格式的展示策略
- **选 A：能提取多少展示多少，同时保留原文入口** — 旧文件也能看到选项和影响；提取不出的部分放进技术详情，另有「查看原文」。
- **选 B：旧格式一律原文展示** — 实现最简单，但非技术用户看到旧文件时体验没有改善。
- **选 C：旧格式直接报错，要求重写** — 格式最统一，但会把历史运行记录变成打不开的文件。
- 推荐：A（旧文件也受益，同时不隐藏原始信息）

## 决策 2：格式不完整时要不要提示
- **选 A：在卡片顶部给一句「该决策请求格式不完整，已尽量提取」** — 用户知道为什么信息少了，不会误以为系统坏了。
- **选 B：静默降级** — 界面更干净，但用户可能困惑。
- 推荐：A（一句提示成本很低，能避免误判）

## 等待期间我还能做什么
- 把两份旧样例加进回归测试，锁住「旧文件也能打开」。
- 准备格式不完整时的截图对照。

## 技术详情
- 旧样例：fixtures/decision-requests/before-1-acceptance-scope.md、before-2-command-scope.md
- 解析入口：parseDecisionRequest(text, { sourceFile, runId })
- 判定字段：parsed.complete / parsed.issues
