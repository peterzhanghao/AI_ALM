## 第二轮：阅读优先的精修（2026-11-04）

设计方向：不是增加装饰，而是让标题、状态、下一步形成稳定阅读顺序。继续沿用宿主主题，不引入字体、依赖或硬编码新配色。

- 修复 narrow 五轨／四格错配，辅列收窄给标题让位；桌面六列、中屏四列、手机两列。
- 用 ResizeObserver 根据实际插件面板内容宽度响应，避免 Desktop 侧栏占宽后仍套桌面列。
- 标题最多两行、14px／1.5 行高；缺陷标记退到元数据行，长 ID 可换行；手机去除重复检查点。
- 项目与范围说明上下分层；交付状态取消胶囊底色，保留真实状态、色点、回滚原因与可访问名称。

## 严苛评审

原界面的主要问题不是颜色，而是层级与操作可信度。

1. 工作视图、来源、搜索及工具在同一视觉平面竞争注意力，迫使用户自己理解信息架构。
2. 每行同时暴露主操作和归档/删除，噪声偏大，危险操作离高频操作太近。
3. 弹窗、上传和反馈分区的键盘行为不完整；鼠标能用不等于交互完整。
4. 保存后离开的旧流程可吞掉保存失败，界面先关闭，用户误以为成功；这比视觉问题更严重。

不能以 Jobs/Musk 会认可之类不可验证结论作为验收标准。本轮采用可测标准：唯一主路径、次要动作渐进展开、键盘可达、错误保留编辑现场。

## 实施

- 工作视图独占第一层横向导航，来源/搜索/工具归为查询层；窄屏保持 DOM 与视觉顺序一致。
- 逐行主动作保留；归档/删除收进原生“更多”展开项，不更改原处理回调。
- 搜索和可交互控件补充焦点样式；尊重 reduced-motion。
- 通用弹窗补初始焦点、Tab/Shift+Tab 循环、aria-modal 和显式关闭按钮；保留返回焦点行为。
- 图片上传可用 Enter/Space 触发；反馈 tabs 支持左右方向键、Home/End 与单一 Tab 入口，tabpanel 正确关联。
- 保存会话离开等待保存完成；失败保留窗口和编辑内容。严格保存遇到迟到/失效响应不再作为成功离开。
- 保留 occurrenceKey、重复 UID、正交来源筛选、现有 detailView 与后端领域语义。未重置仓库原有修改。
